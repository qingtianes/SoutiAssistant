# 鸿蒙“读屏搜题”技术评估

## 需求
像安卓读屏搜题一样，实时读取屏幕上的多道题目并输出答案。安卓用 MediaProjection；鸿蒙无同款 API。

## 可行方案对比

| 方案 | 原理 | 可行性 | 风险 |
|---|---|---|---|
| window.snapshot | 对当前窗口截图 | 中 | 需要前台窗口、权限与真机验证；系统 UI 可能不含在截图内 |
| screenCapture | 屏幕录制/截屏 | 低 | 系统权限限制多，普通应用不可用 |
| 辅助功能/UI 扩展 | 读屏幕内容 | 低 | 开发复杂，需专门 extension 与授权 |
| 保持现有“图片 OCR” | 用户主动截图后识别 | 高 | 已实现，但非实时 |

## 结论
- **当前不建议在无真机验证下实现读屏搜题**，因为屏幕截图类 API 的行为依赖真机/系统版本，盲写代码风险高。
- 建议：把“读屏搜题”留到**最终真机测试阶段**，用真机先验证 `window.snapshot` 可用性与截图范围，再决定实现方案。

## 暂定落地
- 本次先完成扫描搜题；读屏搜题作为真机阶段第一个技术验证项。
